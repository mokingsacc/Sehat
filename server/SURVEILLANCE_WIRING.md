# Wiring the disease watch into worker.js

`server/surveillance.js` is self-contained; worker.js only needs to route to it. `server/surveillance-defs.js` is generated by `python3 tools/build.py` (from `content/src/syndromes.json` and `districts.json`) and must be deployed with the worker.

## 1. Import (top of worker.js)
```js
import * as SURV from './surveillance.js';
```

## 2. Public route: phones send reports (next to `POST /e`)
```js
if (req.method === 'POST' && path === '/r') return SURV.ingest(req, env);
```
The app derives this address from `analyticsUrl` (`.../e` becomes `.../r`), so no config change is needed. CORS headers are set by `ingest`.

## 3. Signed-in routes
Add the paths to `isAdmin`:
```js
|| path === '/watch' || path.startsWith('/watch/')
```
and, after `const me = await whoIs(...)` and the `if (!me) return NOT_FOUND();` line:
```js
if (path === '/watch' || path.startsWith('/watch/')) return SURV.handle(req, env, url, me);
```
`handle` checks roles itself:

| Path | viewer | editor | owner |
|---|---|---|---|
| `GET /watch` (page: alerts, chart, table, searches) | yes | yes | yes (plus the correction form) |
| `GET /watch/methods` | yes | yes | yes |
| `GET /watch/export.csv` / `.json`, `kind=counts|alerts|signals`, `level=shareable` (default) | yes | yes | yes |
| same with `level=full` | 403 | 403 | yes |
| `kind=raw` (every report) and `kind=corrections` | 403 | 403 | yes |
| `POST /watch/correct` (void/restore a report or install, with a reason) | 403 | 403 | yes |

Query parameters for the page and exports: `from`, `to` (ISO weeks like `2026-W41`), or `weeks` (default 12, max 104); optional `syndrome`, `place`.

## 4. A link from the usage dashboard (in `page()`), next to "About this app →"
```js
<a href="/watch?key=${e(key)}" style="font-weight:700">Disease watch →</a>
```

## 5. Database
Run `wrangler d1 execute fhb --remote --file=schema.sql` once more: it adds `surv_reports`, `surv_signals`, `surv_corrections`, `surv_exports` and triggers that refuse UPDATE and DELETE on them (append-only). Nothing else changes.

## Notes
- No changes to `/e`, `TYPES` or `stats()` are needed: reports never go through the usage events.
- `env.SURV_NOW` (milliseconds) overrides "now" for tests only; leave it unset in production.
- Tests: `node scratchpad/test/surveillance-test.mjs` (node:sqlite stand-in for D1).
